# macOS and Linux distribution

Pisi produces native desktop packages for Windows, macOS, and Linux from the
same tagged release workflow.

## macOS artifacts

Every release builds all three macOS architectures:

- Intel x64
- Apple silicon ARM64
- Universal

For each architecture Pisi produces:

- DMG
- ZIP

The application icon is generated by electron-builder from
`assets/pisi.png`.

### Optional Developer ID signing

GitHub secret:

- `MAC_CSC_LINK` — Developer ID Application certificate accepted by
  electron-builder's `CSC_LINK` input.
- `MAC_CSC_KEY_PASSWORD` — certificate password when required.

When no certificate is configured, the release still builds macOS packages,
but the workflow explicitly disables hardened runtime and notarization for the
unsigned build. Unsigned direct-download macOS applications can trigger
Gatekeeper and are intended only for testing/beta distribution.

### Optional Apple notarization

Pisi uses App Store Connect API-key authentication for CI notarization.

GitHub secrets:

- `PISI_APPLE_API_KEY_BASE64` — base64-encoded contents of the downloaded
  App Store Connect `.p8` key.
- `PISI_APPLE_API_KEY_ID`
- `PISI_APPLE_API_ISSUER`

Notarization is enabled only when all three values are present and a Developer
ID signing certificate is also configured.

The workflow writes the API key into the ephemeral GitHub runner, points
electron-builder's `APPLE_API_KEY` to it, and never commits the key.

After packaging, signed builds are validated with `codesign`. Notarized
builds are additionally validated with Gatekeeper (`spctl`) and
`xcrun stapler validate`.

## Linux artifacts

Every release builds:

- x64 AppImage
- ARM64 AppImage
- x64 deb
- ARM64 deb

All packages are validated structurally and included in
`SHA256SUMS-Linux.txt`.

### Optional GPG release signature

Linux does not have one universal application code-signing system equivalent to
Apple Developer ID. Pisi therefore supports an optional detached OpenPGP
signature for the checksum manifest.

GitHub secrets:

- `PISI_GPG_PRIVATE_KEY_BASE64`
- `PISI_GPG_PASSPHRASE` when the key is passphrase-protected

When configured, the workflow publishes:

- `SHA256SUMS-Linux.txt`
- `SHA256SUMS-Linux.txt.asc`

The public verification key should be published separately on Pisi's website or
documentation before users are asked to rely on this signature.

## One release, all platforms

The Windows, macOS, and Linux jobs build in parallel after the validation job.
None of them creates the GitHub Release independently.

A final release job downloads all platform artifacts and creates one Pisi beta
release only after all required packaging jobs succeed. This prevents a
partially published release when one operating system build fails.

Microsoft Store MSIX remains a separate workflow because Store publishing has
its own identity, certification, and signing process.
